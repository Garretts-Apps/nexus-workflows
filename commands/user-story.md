# User story

Need: $ARGUMENTS

No need given? The behavior the branch or conversation is adding. Say which.

A story is a promise of a conversation, written down so nobody forgets what was agreed.

- **As a who, I want what, so that why.** The "so that" is the useful part; it's what lets someone build the right thing when the details shift.
- **Acceptance criteria someone can check:** Given/When/Then or plain bullets, each observable. Include the unhappy path.
- Small enough to finish in a few days. If not, split it; `/feature` helps.
- Dependencies and out-of-scope, briefly.
- Creating a tracker item is outward-facing: **ask** first, and only if a tracker was named.

**Done when** the story has a "so that", checkable criteria including one unhappy path, and fits in a few days.
