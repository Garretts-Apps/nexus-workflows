# Onboard

Focus: $ARGUMENTS

No focus given? The whole repo, for someone who will make their first change this week.

Onboarding is the shortest path from clone to first useful commit. Everything else is a tour.

- **Read before you describe.** README, manifests, entry points, CI config. Name the stack from the files, never from vibes, and only quote versions you saw.
- **How to build, test and run,** as commands. Run them if it's safe and say what happened; a documented command that fails is the first finding.
- **The five files to read first,** in order, with one line each on why.
- **Where things live:** the map of top-level folders, and where a typical change lands.
- **The gotchas:** the setup step everyone gets wrong, the slow test, the generated file you must not edit.
- Reply in chat. Write `docs/onboarding.md` only if a file was asked for.

**Done when** a newcomer could run the tests from the reply alone, and you've said which commands you actually ran.
